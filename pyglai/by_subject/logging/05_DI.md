Để tự động tiêm (Inject) Logger vào các Service bằng Container trong Python, thư viện phổ biến, mạnh mẽ và chuẩn chỉnh nhất hiện nay là `dependency-injector`.

Dưới đây là hướng dẫn chi tiết cách thiết lập một IoC Container (Inversion of Control Container) để tự động quản lý và tiêm `Logger` (tuân thủ cấu hình file/console có màu và cấu trúc DDD/SOLID đã làm ở các bước trước).

## Bước 1: Cài đặt thư viện dependency-injector

Bạn chạy lệnh sau trong terminal:
    
    
    pip install dependency-injector
    

## Bước 2: Triển khai cấu trúc Container nâng cao

Chúng ta sẽ tạo một cấu trúc code hoàn chỉnh gồm: Interface Logger, Lớp cài đặt cụ thể, Service nhận Logger, và IoC Container quản lý vòng đời của chúng.
    
    
    import logging
    from abc import ABC, abstractmethod
    from dependency_injector import containers, providers
    
    # ==========================================
    # 1. DOMAIN LAYER: Định nghĩa Interface
    # ==========================================
    class IAppLogger(ABC):
        @abstractmethod
        def info(self, msg: str) -> None: pass
        @abstractmethod
        def error(self, msg: str) -> None: pass
    
    
    # ==========================================
    # 2. INFRASTRUCTURE LAYER: Cài đặt cụ thể
    # ==========================================
    class PythonAppLogger(IAppLogger):
        def __init__(self, logger_name: str):
            # Lấy logger đã được cấu hình từ dictConfig trước đó
            self._logger = logging.getLogger(logger_name)
    
        def info(self, msg: str) -> None:
            self._logger.info(msg)
    
        def error(self, msg: str) -> None:
            self._logger.error(msg, exc_info=True)
    
    
    # ==========================================
    # 3. APPLICATION LAYER: Service nhận Logger
    # ==========================================
    class OrderService:
        # Service KHÔNG tự khởi tạo logger, nó yêu cầu logger thông qua __init__ (DI)
        def __init__(self, logger: IAppLogger):
            self.logger = logger
    
        def process_order(self, order_id: str):
            self.logger.info(f"Đang xử lý đơn hàng: {order_id}")
            # Logic nghiệp vụ...
    
    
    # ==========================================
    # 4. IOC CONTAINER: Nơi quản lý và tự động tiêm
    # ==========================================
    class AppContainer(containers.DeclarativeContainer):
        # Chỉ định cấu hình của Container
        config = providers.Configuration()
    
        # Khởi tạo đối tượng Logger dưới dạng Factory (Mỗi lần gọi tạo một thực thể mới)
        # Hoặc có thể dùng providers.Singleton(PythonAppLogger, logger_name="app") nếu muốn dùng chung một instance
        logger_factory = providers.Factory(
            PythonAppLogger,
            logger_name="app_project"  # Truyền tên logger vào __init__ của PythonAppLogger
        )
    
        # Tự động tiêm logger_factory vào OrderService
        order_service = providers.Factory(
            OrderService,
            logger=logger_factory  # Container tự động lấy instance từ logger_factory để nạp vào đây
        )
    

## Bước 3: Cách sử dụng tại File chạy chính (`main.py`)

Khi chạy ứng dụng, bạn chỉ cần gọi Container ra và lấy Service mong muốn. Bạn không cần quan tâm Service đó cần những tham số gì, Container đã tự động "lắp ráp" chúng lại với nhau.
    
    
    # Giả sử bạn đã gọi hàm setup_logging() ở câu trả lời trước tại đây để cấu hình màu sắc/file xoay vòng
    
    if __name__ == "__main__":
        # 1. Khởi tạo Container của ứng dụng
        container = AppContainer()
    
        # 2. Lấy Service ra (Container đã tự động tiêm Logger vào bên trong)
        order_service = container.order_service()
    
        # 3. Sử dụng Service bình thường
        order_service.process_order("ORDER-2026-999")
    

## Tại sao cách làm này tối ưu cho dự án DDD/SOLID?

  1. Loose Coupling (Liên kết lỏng lẻo): `OrderService` chỉ biết đến `IAppLogger` (Interface). Nếu sau này bạn muốn đổi sang log bằng thư viện khác (ví dụ: `Loguru`, `Structlog`) hoặc gửi thẳng lên dịch vụ Cloud (AWS CloudWatch, Datadog), bạn chỉ cần tạo một class mới tuân thủ `IAppLogger` và cập nhật đúng một dòng trong `AppContainer`. Toàn bộ code xử lý nghiệp vụ của `OrderService` giữ nguyên (Tuân thủ nguyên tắc Open/Closed).
  2. Quản lý tập trung: Toàn bộ vòng đời cấu hình, khởi tạo, kết nối phụ thuộc giữa các class được quy về một mối duy nhất là `AppContainer`. Code của bạn sẽ cực kỳ sạch sẽ và dễ viết Unit Test (bạn có thể dễ dàng tiêm một `MockLogger` vào Service khi test).
