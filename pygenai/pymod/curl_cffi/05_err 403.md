Lỗi **HTTP 403 Forbidden** hoặc **Cloudflare Block** xuất hiện khi hệ thống Anti-bot phát hiện request của bạn không đến từ một trình duyệt người dùng thực sự.

Mặc dù `curl_cffi` hỗ trợ giả lập TLS fingerprint vượt trội hơn các thư viện truyền thống, các tường lửa như Cloudflare, Akamai hay Datadome vẫn sử dụng nhiều lớp kiểm tra khác.

---

### Nguyên nhân & Giải pháp chi tiết

#### 1. TLS Fingerprint / Version không khớp với `impersonate`

* **Nguyên nhân:** Khai báo phiên bản `impersonate` quá cũ hoặc hệ thống vừa cập nhật thuật toán phát hiện chuỗi TLS Handshake.
* **Giải pháp:** Cập nhật `curl_cffi` lên bản mới nhất và sử dụng các bản trình duyệt Chrome/Safari gần nhất.

```python
from curl_cffi import requests

# Cập nhật phiên bản trình duyệt mới hơn (ví dụ: chrome120, chrome124)
response = requests.get(
    "https://example.com", 
    impersonate="chrome120" # Thử đổi sang "safari17_0" hoặc "edge101" nếu vẫn bị block
)

```

#### 2. Thiếu hoặc Sai lệch HTTP Headers (Header Anomaly)

* **Nguyên nhân:** Khi dùng `impersonate`, `curl_cffi` tự sinh TLS fingerprint nhưng **không tự điền đầy đủ tất cả HTTP Headers** của trình duyệt. Việc thiếu `User-Agent`, `Accept-Language`, hoặc các header `Sec-Ch-Ua-*` sẽ khiến request bị cờ đỏ.
* **Giải pháp:** Khai báo bộ Header chuẩn của trình duyệt tương ứng với chuỗi `impersonate`.

```python
headers = {
    "User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/120.0.0.0 Safari/537.36",
    "Accept": "text/html,application/xhtml+xml,application/xml;q=0.9,image/avif,image/webp,*/*;q=0.8",
    "Accept-Language": "en-US,en;q=0.9",
    "Sec-Ch-Ua": '"Not_A Brand";v="8", "Chromium";v="120", "Google Chrome";v="120"',
    "Sec-Ch-Ua-Mobile": "?0",
    "Sec-Ch-Ua-Platform": '"Windows"',
    "Sec-Fetch-Dest": "document",
    "Sec-Fetch-Mode": "navigate",
    "Sec-Fetch-Site": "none",
    "Sec-Fetch-User": "?1",
    "Upgrade-Insecure-Requests": "1"
}

response = requests.get("https://example.com", headers=headers, impersonate="chrome120")

```

#### 3. IP bị gắn cờ xấu (IP Reputation / Datacenter IP Block)

* **Nguyên nhân:** Cloudflare chặn trực tiếp dải IP đến từ các nhà cung cấp VPS/Hosting (AWS, DigitalOcean, Hetzner, Vultr...).
* **Giải pháp:** Sử dụng **Residential Proxy** (Proxy dân cư) hoặc **Mobile Proxy** thay vì Datacenter Proxy.

```python
proxies = {
    "http": "http://user:pass@residential-proxy.com:8080",
    "https": "http://user:pass@residential-proxy.com:8080",
}

response = requests.get("https://example.com", proxies=proxies, impersonate="chrome120")

```

#### 4. Chưa vượt qua lượt Challenge / Cần Token `cf_clearance`

* **Nguyên nhân:** Trang web bật chế độ Cloudflare Turnstile hoặc JavaScript Challenge (Under Attack Mode). `curl_cffi` không tự thực thi mã JavaScript để giải đố được.
* **Giải pháp:**
1. Dùng Selenium/Playwright hoặc dịch vụ giải captcha (2captcha, CapSolver) để lấy cookie `cf_clearance` và `User-Agent`.
2. Truyền cookie này vào `curl_cffi` để cào hàng loạt với tốc độ cao.



```python
cookies = {
    "cf_clearance": "x1y2z3_your_passed_turnstile_token_here"
}

response = requests.get("https://example.com", cookies=cookies, impersonate="chrome120")

```

#### 5. Tốc độ Request quá nhanh (Rate Limiting)

* **Nguyên nhân:** Gửi quá nhiều request trong thời gian ngắn từ cùng một Session/IP.
* **Giải pháp:** Thêm thời gian nghỉ ngơi ngẫu nhiên (`time.sleep`) hoặc xoay vòng IP (Proxy Rotation).

### Check-list khắc phục nhanh theo thứ tự

1. **Nâng cấp thư viện:** `pip install curl_cffi --upgrade`
2. **Thay đổi target:** Đổi `impersonate="chrome120"` sang `safari17_0` hoặc `chrome110`.
3. **Thêm Header chuẩn:** Đảm bảo có đủ `User-Agent`, `Referer`, `Accept-Language`.
4. **Đổi IP:** Kiểm tra xem IP hiện tại có bị Cloudflare ban không bằng cách dùng Proxy dân cư.
