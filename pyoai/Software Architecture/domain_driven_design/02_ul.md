# 11\. Ví dụ hoàn chỉnh

Giả sử thiết kế hệ thống đọc truyện.
    
    
    from dataclasses import dataclass, field
    
    
    @dataclass
    class Chapter:
        number: int
        title: str
        content: str
    
    
    @dataclass
    class Novel:
        title: str
        chapters: list[Chapter] = field(default_factory=list)
    
        def add_chapter(self, chapter: Chapter):
            self.chapters.append(chapter)
    
        def remove_chapter(self, number: int):
            self.chapters = [
                c for c in self.chapters
                if c.number != number
            ]
    
        def rename(self, new_title: str):
            self.title = new_title

Đọc code giống như đang đọc tài liệu nghiệp vụ:
    
    
    Novel
    
    ↓
    
    add_chapter()
    
    ↓
    
    rename()
    
    ↓
    
    remove_chapter()

Không cần giải thích nhiều.

# 16\. Best Practices

✔ Đặt tên theo nghiệp vụ, không theo công nghệ.

✔ Tránh các tên chung chung như:

  * Manager 
  * Helper 
  * Util 
  * Processor 
  * Handler (trừ khi đúng ý nghĩa nghiệp vụ) 



✔ Dùng danh từ cho Entity, Value Object, Repository.

✔ Dùng động từ hoặc cụm động từ cho hành vi (`borrow`, `publish`, `crawl`, `deposit`...).

✔ Khi BA hoặc chuyên gia nghiệp vụ thay đổi thuật ngữ, cân nhắc cập nhật ngôn ngữ trong code để giữ sự nhất quán.

## Tổng kết

Sau buổi học này, bạn nên ghi nhớ:

  * **Ubiquitous Language** là ngôn ngữ chung giữa chuyên gia nghiệp vụ và đội phát triển. 
  * Tên lớp, phương thức, API, bảng dữ liệu và tài liệu nên sử dụng **cùng một thuật ngữ** để tránh hiểu nhầm. 
  * Code DDD nên "kể lại câu chuyện nghiệp vụ", thay vì chỉ mô tả các thao tác kỹ thuật như `update()` hay `process()`. 
  * Một Ubiquitous Language tốt sẽ giúp hệ thống dễ đọc, dễ bảo trì và dễ mở rộng trong nhiều năm. 



Ở **Buổi 3** , chúng ta sẽ đi sâu vào **Domain, Core Domain, Supporting Domain và Generic Subdomain** — nền tảng để xác định phần nào của hệ thống là quan trọng nhất và nên đầu tư thiết kế theo DDD.
